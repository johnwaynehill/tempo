## Design Context

### Users
People with ADHD who need a distraction-reduced productivity tool for todos, notes, and habits. Used daily on Mac and iPhone (PWA). The job: capture thoughts in under 3 seconds, focus on <=5 prioritized items, and build sustainable habits — all without cognitive overload. Context is often fragmented attention, so every interaction must earn its place.

### Brand Personality
**Calm, Minimal, Warm.** Tempo feels like a trusted journal, not a productivity app. The voice is quiet and encouraging — never urgent, never gamified. It speaks only when spoken to and stays out of the way the rest of the time.

### Aesthetic Direction
- **Visual tone:** "The Quiet Rhythm" — spacious layouts, generous whitespace, muted sage palette, tonal depth over drop shadows, no 1px borders
- **References:** Things 3 (spatial calm, subtle animations), Linear (crisp typography, dark-mode polish), Apple Notes/Reminders (native-feeling, zero learning curve)
- **Anti-references:** Notion (too complex/feature-dense), Todoist (too corporate/gamified), Jira (enterprise overhead). If it feels like "work software," it's wrong.
- **Theme:** Light and dark mode. Primary: muted sage (#4f645b). Surfaces: warm off-whites (#f9f9f8) and deep near-blacks (#1a1c1b). Never pure white or pure black.
- **Typography:** Manrope (display, 500-800) + Inter (body, 400-600). Minimum 1.6x line-height for ADHD readability.

### Design Principles

1. **Calm over clever.** Every element should reduce cognitive load, not add to it. When in doubt, remove.
2. **Warmth over sterility.** Muted tones, soft radii, and generous spacing make the interface feel human — like paper, not software.
3. **Capture speed is sacred.** Nothing should stand between a thought and its capture. 3-second rule for any input action.
4. **Progressive disclosure.** Show only what's needed now. Actions, settings, and details reveal themselves contextually — hover, tap, or expand.
5. **Native-feeling on every device.** On iPhone it should feel like an Apple app. On Mac it should feel like a desktop-class tool. Respect platform conventions, safe areas, and input methods.

### Tech Stack
- React 19 + TypeScript + Vite 8
- Tailwind CSS 4 (inline @theme tokens in index.css, no config file)
- Firebase (Firestore real-time + offline persistence, Auth, Cloud Functions)
- Milkdown (Markdown editor, Nord theme)
- PWA via vite-plugin-pwa + Workbox
- Custom components only — no external UI library

### Design Tokens (reference)
Defined as CSS custom properties in `/src/index.css` via `@theme`:
- Surfaces: `--color-surface` through `--color-surface-container-highest`
- Primary: `--color-primary`, `--color-primary-dim`
- Text: `--color-on-surface`, `--color-on-surface-variant`
- Error: `--color-error` (muted, never pure red)
- Borders: `--color-outline-variant` at 15% opacity (ghost borders only)
- Radii: `--radius-lg` (1rem), `--radius-xl` (1.5rem)
- Animations: 300ms ease-out for interactions, 0.3-0.5s for reveals

### Responsive Strategy
- Single breakpoint: `md:` (~768px)
- Mobile: BottomNav (5 items), drawers slide up, MobileFormatBar above keyboard
- Desktop: Sidebar (sticky, w-52), centered modals
- Safe areas: `env(safe-area-inset-*)` for iOS PWA notch/home indicator
